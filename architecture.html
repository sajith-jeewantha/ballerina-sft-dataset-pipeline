Ballerina SFT Dataset Pipeline

Builds supervised fine-tuning datasets for Qwen3.8-27B on Ballerina Swan Lake 2201.14.1. A knowledge graph decides what to cover; prompts are written per graph item and reviewed; the teacher's answers are checked with the real bal toolchain and repaired with its errors; real projects give codebase tasks; a held-out eval set keeps training data clean; and sftgen assemble turns it all into SFT, DPO and CPT data with a dataset card. Every step is tracked in one SQLite database with an HTML report.

Principles

Verified by the toolchain, driven by coverage, kept clean of the eval set.

Pinned, licence-gated sources

One Swan Lake update (2201.14.1) pinned in sources.lock.json. Only permissive repositories, each recorded in the licence register.

Coverage from a knowledge graph

Prompts are planned per graph item, with budgets by priority, task type and difficulty. The dataset card reports coverage per item.

The toolchain is the judge

Answer code is built with bal and repaired with the real errors. A judge from a different model family checks only prose.

Eval set held out

30% of BBE, translated benchmarks and eval-split codebases are fingerprinted. Every export drops copies and near-copies of them.

Never run model code by default

Tests are type-checked, not executed. Running them needs an explicit opt-in flag, in a sandbox.

Small runs, one switch

Limits bound each run; re-runs never repeat finished work. One flag mirrors the same layout to GCS or S3.

End-to-end data flow

Every phase reads from and writes to data/pipeline.db. The report is rebuilt after every command, and with STORAGE_BUCKET=true the outputs are pushed to the bucket.

No vector database. Retrieval is an exact item-to-source lookup from the graph, plus SQLite FTS5 (BM25) over chunks and a symbol table parsed from the Central API docs, all inside pipeline.db.

The dataset

sftgen assemble writes data/datasets/v1/ with no model calls, so you can re-run it after every gap-fill round.

Assembly steps

  1. Sources: verified and judged prompt answers (standalone and codebase), chunk-grounded Q&A, and mined fixes (opt in)
  2. Decontaminate: every sample is checked against the eval fingerprints
  3. Dedup: exact and MinHash near-duplicate prompts; the better sample wins
  4. Balance: caps per item (core 14, important 9, long tail 5), round-robin over task × difficulty × context mode
  5. Split: 3% validation by codebase, page or prompt group

The report

A short terminal summary after every command, and data/reports/report.html: one file, no server.

Contents

  • Knowledge graph coverage per node and priority
  • Code repositories, licences and token counts
  • Eval set, decontamination, baselines and pass@k per item
  • Prompts, answers (pass, first-try and repair rates), codebase pool
  • Raw corpus and mined fixes
  • Dataset: composition, coverage and items under budget
  • Pages, chunks, Q&A, run history, tokens and cost per phase

Configuration

Precedence: environment variable > .env > config/pipeline.yaml > code default. Empty values in .env are ignored. Values are checked at startup.

OPENROUTER_API_KEY · LLM_BASE_URLLLM access (any OpenAI-compatible endpoint)
ANSWER_GEN_MODELThe teacher (DeepSeek); also the prompt writer by default
JUDGE_MODEL · QUESTION_GEN_MODELReviewer and judge, from a different model family
GITHUB_TOKENGitHub API rate limit
LIMIT_* · QUESTIONS_PER_CHUNK · REQUEST_DELAY_SECONDSRun limits
STORAGE_BUCKET · STORAGE_PROVIDER · BUCKET_NAMEMirror outputs to GCS or S3

config/pipeline.yaml (committed)

How to run

Steps without a model need no key. Start model phases with small limits, check the report, then set LIMIT_GENERATING=0.

1

Set up once

git clone https://github.com/sajith-jeewantha/ballerina-sft-dataset-pipeline.git
cd ballerina-sft-dataset-pipeline
python3.11 -m venv .venv && source .venv/bin/activate
pip install -e shared -r scraper/requirements.txt -e scraper \
  -r sft-dataset-generator/requirements.txt -e sft-dataset-generator -r requirements-dev.txt
cp .env.example .env   # API key, models, GITHUB_TOKEN, limits
2

Collect, hold out the eval set, build the pool and corpus (no model calls)

sftgen scrape && sftgen graph sync
LIMIT_REPOS=0 sftgen collect-repos
sftgen build-eval
sftgen codebases build && sftgen codebases verify
sftgen corpus && sftgen mine-fixes
3

Prompts, verified answers and the eval set (model calls)

sftgen plan-prompts
LIMIT_GENERATING=0 sftgen generate-prompts
sftgen codebases attach
LIMIT_GENERATING=0 sftgen answer-prompts
sftgen eval fetch && sftgen eval translate && sftgen eval tasks && sftgen eval ecosystem
sftgen eval run --model base
4

Assemble the dataset and check it

sftgen assemble
open data/datasets/v1/CARD.md data/reports/report.html

Re-running and resuming

PhasePicks up
scrape · collect-reposPages and repos not yet stored, plus failed ones. --refresh re-checks them; --update-lock re-pins.
generate-promptsOpen slots in the plan: rejected or missing prompts are refilled, up to prompts.max_rounds writer calls per item.
answer-promptsAccepted prompts without a response; --retry-failed gives failed ones another round of repairs.
codebases buildFills the pool to pool_size, and adds any state kinds that are missing.
mine-fixes · eval translateRepos not yet mined; problems not yet translated.
assembleRebuilds the whole version from the database each time; gap-fill, then re-run.
CachesLLM responses, compile results and clones on disk, so repeated work costs nothing.

Reliability, politeness and safety

ConcernApproach
Scrapingrobots.txt checked before every web page. One honest User-Agent and a delay between requests; no proxies or rotation. Git snapshots and git ls-remote instead of API quota.
LicencesA pre-gate on GitHub's licence, then a gate on the LICENSE text. Copyleft and unlicensed repos are excluded. Every repo is in the register; the card and ATTRIBUTION files list what was used.
Eval leakageExact, MinHash and shingle-containment fingerprints. Overlaps are flagged in every table and dropped from every export, and the written files are re-checked.
Model-written codeCompiled only: temp folder, --offline first, timeout, heap cap, secrets removed from the environment. Tests are type-checked as sources. Running them needs answers.run_tests, codebases.run_tests or eval.run_tests, in a sandbox.
Failures and costRecorded per row and shown in the report; one failure never stops a run. Every call's tokens and cost are stored.
SecretsOnly in the environment. Never logged or stored in the database.
